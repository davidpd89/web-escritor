## 7. Qué está bien y debe preservarse

### 7.1 · No redirect automático a Home

Una URL inexistente permanece como error con explicación útil. No se esconde detrás de `/`.

### 7.2 · HTTP correcto

El estado HTTP real es parte esencial del contrato. `noindex` no compensa un soft-404 200.

### 7.3 · Recuperación múltiple

La página ofrece destinos estables sin adivinar agresivamente intención del usuario.

### 7.4 · Coherencia de shell

No parece un micrositio legacy separado del resto de la web.

### 7.5 · Sin JS obligatorio

La navegación esencial debe funcionar aunque JS falle.

## 8. Mejoras opcionales: no forman parte de A.10

### Reporte de enlace roto

Solo con necesidad operativa y canal útil. Un `mailto:` podría ser suficiente, pero puede añadir spam/ruido. No es necesario para considerar A.10 cubierta.

### Búsqueda/Pagefind

Si la búsqueda está estable y datos reales muestran que usuarios de 404 la necesitan, podría evaluarse. No añadir un buscador pesado por checklist.

### Analítica de recuperación

La matriz intermedia mencionó medir clicks. Solo instrumentarlo si responde una pregunta real y encaja con la política de analítica/privacidad. No convertir la 404 en una superficie de tracking especial.

## 9. Contrato que debe preservarse

1. URL inexistente → HTTP 404.
2. Body útil de `404.html`.
3. `noindex`.
4. sin canonical a Home.
5. sin redirect automático a Home.
6. shell/navegación funcionales.
7. links de recuperación válidos.
8. usable sin JS.
9. reflow/accesibilidad bajo gates globales.
10. no indexar rutas de error como contenido real.

## 10. Test recomendado

Mantener, si no existe ya de forma equivalente:

```js
const response = await page.goto(`${origin}/__ruta-que-no-existe__`);
assert.equal(response.status(), 404);
assert.match(await page.title(), /Página no encontrada/);
assert.equal(
  await page.locator('meta[name="robots"]').getAttribute('content'),
  'noindex,follow'
);
await expect(page.locator('a[href="/"]')).toBeVisible();
```

Y smoke HTTP de producción para una ruta inexistente controlada cuando se modifica infraestructura/deploy.

No crear un segundo test SEO si `global-discoverability-browser` ya cubre exactamente estos invariantes.

## 11. Qué NO hacer

- responder 200 a URL inexistente;
- redirigir 404 a Home;
- canonicalizar 404 a `/`;
- añadir keywords/contenido SEO a la página de error;
- recomendaciones personalizadas mediante tracking solo para 404;
- cargar servicio pesado de búsqueda sin evidencia;
- múltiples 404 por sección;
- indexar la 404;
- rediseñarla solo porque A.10 existe en una lista;
- marcar una mejora opcional como deuda de la idea original.
