# npm audit — verificación 2026-09-10

Contexto: la CI de PR #488 reportó 17 vulnerabilidades (11 high, 4 moderate, 2 low) en `npm ci`. Una revisión externa (GPT) señaló que la justificación previa ("10 high, solo dev") estaba desactualizada y pidió evidencia fresca de `npm audit --omit=dev` y `npm audit --json` antes de descartarlas. Esta es esa evidencia.

## Resultado

```
npm audit --omit=dev --json  →  0 vulnerabilidades (info/low/moderate/high/critical todo en 0)
npm audit --json (con dev)   →  17 vulnerabilidades: 11 high, 4 moderate, 2 low, 0 critical
```

Coincide exactamente con lo reportado en la CI de #488 — no hay discrepancia que investigar.

## Origen: dos árboles de dependencias de devDependencies, nunca en producción

`package.json` no tiene ninguna `dependencies` de producción (el sitio es HTML/CSS/JS estático sin runtime de npm). Las 17 vulnerabilidades cuelgan por completo de dos herramientas de CI, ambas en `devDependencies`:

- **`@lhci/cli`** (Lighthouse CI) — vía `puppeteer` → `puppeteer-core` → `@puppeteer/browsers` → `extract-zip`, y vía `lighthouse` → `@lhci/utils`, `inquirer` → `external-editor` → `tmp`, `js-yaml`, `uuid`.
- **`pa11y-ci`** (accesibilidad CI) — vía `pa11y` → `puppeteer` (mismo árbol de arriba).

Ninguno de los dos paquetes se ejecuta en el sitio publicado; solo corren dentro de los workflows de GitHub Actions (`lighthouse`, `pa11y-baseline`) contra el HTML ya generado.

## Decisión

Se mantiene la postura de no tocar estas dependencias por ahora:

- **No** se ejecuta `npm audit fix --force` (instrucción explícita del usuario/GPT de no hacerlo sin revisión — arriesga romper `@lhci/cli`/`pa11y-ci` al forzar mayores incompatibles).
- **No** hay riesgo de producción: `--omit=dev` da 0.
- Revisar en una futura sesión (con más margen de créditos) si `@lhci/cli`/`pa11y-ci` tienen versiones mayores publicadas que resuelvan estas cadenas de transitorias sin romper la configuración actual de `lighthouserc.json`/`.pa11yci.json`.
