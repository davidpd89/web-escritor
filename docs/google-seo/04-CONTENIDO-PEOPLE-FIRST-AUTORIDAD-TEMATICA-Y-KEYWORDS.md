# 04 — Contenido people-first, autoridad temática y keywords

## Objetivo

Usar demanda de búsqueda para descubrir necesidades reales sin convertir el sitio en contenido escrito para un algoritmo.

Google define como prácticas centrales:

- contenido útil, fiable y creado para personas;
- información original/reporting/research/analysis;
- experiencia de primera mano;
- palabras que las personas realmente usan en title, heading, alt y anchor;
- una audiencia y propósito reconocibles.

---

# 1. People-first gate

Antes de crear una URL indexable, responder por escrito:

1. ¿Quién es el usuario?
2. ¿Qué quiere conseguir/aprender?
3. ¿Por qué este sitio tiene legitimidad o experiencia para responder?
4. ¿Qué aporta que no sea una síntesis genérica?
5. ¿Puede quedar satisfecho sin volver a Google inmediatamente?
6. ¿Existe ya una URL nuestra que debería resolverlo?
7. ¿La publicaríamos aunque Google no enviara tráfico?

Si la respuesta a 4 o 7 es «no», no debería ser una prioridad SEO.

---

# 2. Who / How / Why

## Who

Cuando importe, dejar claro quién crea el contenido.

Para Cuaderno:

- byline David Porto Díaz;
- enlace a Autor;
- contexto real cuando la pieza parte de experiencia personal.

No añadir bios artificiales de 200 palabras a cada página.

## How

Explicar metodología cuando aporta confianza.

Especialmente importante en:

- editoriales;
- convocatorias;
- herramientas;
- análisis propios;
- rankings/recomendaciones;
- datasets.

Ejemplo:

> Verificamos cada convocatoria contra la fuente oficial y mostramos la fecha de revisión.

es más valioso que afirmar simplemente «información actualizada».

## Why

La razón principal debe ser ayudar al lector/usuario.

No:

> Este artículo se ha creado para posicionar por “mejores editoriales fantasía España”.

Sí:

> Ayudar a un autor a saber qué editoriales reciben manuscritos y cómo verificarlo.

---

# 3. E-E-A-T

Experience, Expertise, Authoritativeness, Trust son marcos útiles para evaluar calidad. No deben convertirse en un checklist de «señales de ranking» inventadas.

## Para este sitio

### Experience

Activos reales:

- proceso de escritura de los libros;
- publicación;
- ferias/firma;
- construcción de Noveris;
- trabajo editorial;
- uso y construcción de herramientas;
- experiencia como autor.

### Expertise

Demostrar mediante contenido preciso y metodología.

No exagerar credenciales ajenas al tema.

### Authoritativeness

Se construye con:

- obras publicadas;
- editorial;
- premios verificables;
- referencias externas;
- perfiles bibliográficos;
- enlaces/menciones legítimas;
- profundidad temática.

### Trust

Prioridad superior:

- hechos correctos;
- fuentes;
- disclosure afiliado;
- privacidad;
- contacto;
- correcciones;
- fechas honestas;
- no reviews falsas;
- no ofertas inventadas.

---

# 4. Keyword research

No construir estrategia sobre herramientas que prometen «ranking difficulty exacta» como si conocieran el algoritmo de Google.

## Fuentes prioritarias

1. Search Console queries reales.
2. Search Console Insights.
3. Google Trends para evolución relativa/interés.
4. SERP manual para entender intent.
5. preguntas reales de lectores/escritores.
6. autocomplete/related searches como ideación, no como obligación editorial.
7. herramientas third-party solo como estimaciones.

# 6. Mapping keyword → intent → URL

Nunca guardar una lista de 2.000 keywords sin asignación.

Tabla de trabajo:

| Query cluster | Intent | Current owner | Action |
|---|---|---|---|
| qué es portal fantasy | informational | article | improve |
| portal fantasy español libros | recommendation | recommendations | validate |
| Samuel entre mundos | navigational/book | Samuel page | protect |
| contador palabras | tool | word counter | measure |
| editoriales manuscritos | directory | editoriales | validate |

## Estados de action

- protect;
- improve;
- merge;
- split;
- new only if gap;
- noindex;
- ignore.

---

# 7. No existe un word count ideal

Google dice explícitamente que no tiene un word count preferido.

Por tanto:

- una herramienta puede necesitar 300 palabras;
- una guía puede necesitar 2.500;
- una ficha de editorial puede necesitar 500;
- una respuesta concreta puede necesitar 150.

Escribir hasta resolver la tarea, no hasta un contador arbitrario.

---

# 8. Freshness

Google tiene sistemas de freshness cuando una query la necesita.

No significa que cambiar la fecha mejore una página evergreen.

## Cambiar `dateModified` cuando

- se revisan hechos;
- se añade investigación material;
- cambia disponibilidad;
- se actualiza una lista sustancialmente;
- cambia una normativa/requisito;
- se incorpora un bloque relevante.

## No cambiar cuando

- se corrige una coma;
- cambia el footer;
- se actualiza copyright;
- se regenera CSS;
- se quiere «parecer reciente».

---

# 9. Content refresh framework

Para una página con pérdida:

1. comprobar update/incidente de Google;
2. segmentar queries afectadas;
3. revisar intent actual de SERP;
4. comprobar exactitud;
5. comprobar calidad/experiencia;
6. comparar con el contenido que satisface mejor la query;
7. mejorar lo que falte;
8. no cambiar todo a la vez;
9. anotar release;
10. medir.

No «actualizar 100 artículos» porque uno haya caído.

# 10. Contenido original prioritario

## 10.1 Noveris / worldbuilding

Gran ventaja porque David es fuente primaria.

Ideas de alto valor:

- por qué la magia tiene coste;
- decisiones descartadas al construir Noveris;
- cómo se evita la magia sin límites;
- diseño de facciones;
- objetos con memoria;
- cómo se diseña un portal narrativo;
- mapas/proceso si existen materiales reales publicables.

## 10.2 Manecillas

First-party:

- anatomía de una novela coral;
- cómo se conecta un objeto a múltiples vidas;
- decisiones sobre voz/época;
- investigación real usada;
- proceso editorial con Monza solo con información publicable;
- notas de autor sin spoilers;
- guía de lectura/club cuando esté lista.

## 10.3 Experiencia como autor

- Feria del Libro: aprendizajes concretos;
- preparación de press kit;
- cómo preparar una página de libro;
- metadatos de publicación;
- experiencia con eventos.

Evitar generalidades del tipo «10 consejos para escribir mejor» salvo que haya enfoque propio.

## 10.4 Herramientas con metodología

Cada herramienta puede generar autoridad si además de funcionar explica:

- algoritmo/regla;
- limitaciones;
- privacidad;
- casos donde no usarla;
- ejemplos;
- interpretación.

# 11. Directorios y contenido escalado

Google define scaled content abuse como muchas páginas creadas principalmente para manipular Search y con poco valor, independientemente de si las genera IA, humanos o scraping.

## Riesgo en este proyecto

- cientos de editoriales;
- convocatorias;
- fichas automatizadas;
- perfiles de recursos.

## Defensa

Index quality gate.

Una ficha no entra al sitemap hasta tener, por ejemplo:

- nombre verificado;
- URL oficial;
- estado;
- evidencia de manuscritos cuando se afirma;
- género/encaje solo si fuente;
- fecha de verificación;
- nota editorial única;
- información accionable.

No indexar placeholders.

---

# 12. Recomendaciones y reviews system

Google tiene un reviews system para contenido first-party de opinión/recomendación.

Las listas de lectura deben ser más profundas que un resumen de sinopsis.

## Buen contenido

- experiencia real con la obra cuando exista;
- criterio de inclusión;
- diferencias;
- para quién encaja;
- qué puede no gustar;
- evidencia;
- comparaciones útiles.

## Malo

- 20 libros con descripciones de retailer reescritas;
- rankings sin criterio;
- Samuel en #1 siempre;
- copiar ratings externos;
- poner «mejor» sin evaluación.

### Transparencia

Si un enlace es afiliado, declarar/qualify.

Si Samuel es del propio autor, la relación es obvia pero puede indicarse donde ayude a confianza.

---

# 13. Content pruning

No borrar contenido masivamente para «subir la calidad media» sin evidencia.

Opciones:

- improve;
- merge + 301;
- noindex si sigue útil fuera de Search;
- retire 404/410 si no tiene valor;
- leave.

El actual artículo retirado de Noveris demuestra un patrón válido: conserva URL/navegación pero no se indexa.

---

# 14. Duplicate intent vs duplicate text

Google puede manejar algo de contenido duplicado; el problema estratégico es tener múltiples páginas sin una razón clara.

No obsesionarse con porcentajes de «duplicate content» de tools de terceros.

Priorizar:

- canonical;
- intent;
- utilidad;
- consolidación de señales.

---

# 15. Search-engine-first anti-signals

Preguntas de control:

- ¿estamos produciendo muchos temas esperando que alguno rankee?;
- ¿usamos automatización para publicar sin revisión?;
- ¿resumimos otras fuentes sin añadir valor?;
- ¿escribimos sobre algo solo porque está trending?;
- ¿fingimos que una página se actualizó?;
- ¿añadimos texto hasta una cifra de palabras?

Si sí, parar.

---

# 16. Generative AI para crear contenido

Google no prohíbe usar IA como herramienta.

Puede servir para:

- estructurar investigación;
- detectar gaps;
- editar;
- resumir notas propias;
- generar alternativas para revisión;
- transformar formatos.

No usar para:

- generar cientos de URLs;
- inventar experiencia;
- inventar fuentes;
- inventar editoriales/concursos;
- reviews falsas;
- reescribir páginas competidoras;
- publicar sin fact-check.

Todo contenido indexable debe pasar control editorial humano/factual.

# 17. Content brief SEO recomendado

Antes de escribir:

```text
Audience:
User job:
Primary intent:
Existing URL owner:
Why new URL is needed:
Original contribution:
First-party evidence:
Primary sources:
Entities:
Internal links in:
Internal links out:
Potential schema:
Freshness requirement:
Conversion secondary:
Index/noindex:
```

Después de escribir:

```text
Does it fully resolve intent?
Any unsupported factual claim?
Any copied/derived passage?
Does title match actual content?
Is author/byline appropriate?
Are dates honest?
Are images meaningful?
Is promotion subordinate to user job?
```

---

# 18. Content portfolio targets

No fijar cuotas de artículos/semana.

Preferir una cartera equilibrada:

- evergreen definitions/guides;
- first-party case studies;
- real-time/fresh resources;
- tools;
- book/entity pages;
- event/news moments;
- recommendations with genuine analysis.

## Cadencia

Publicar cuando hay algo que merece URL.

No existe beneficio SEO conocido por publicar X veces a la semana de manera artificial.

---

# 19. Google Trends

Uso recomendado:

- comparar términos (`portal fantasy` vs variantes españolas);
- detectar estacionalidad (`Feria del Libro`, concursos);
- no interpretar 0–100 como volumen absoluto;
- no crear contenido solo por un pico de un día.

Combinar con Search Console.

---

# 20. Acceptance criteria

- todo contenido nuevo pasa people-first gate;
- keyword cluster tiene URL owner;
- no pages-per-variant;
- no word-count targets arbitrarios;
- fechas honestas;
- directorios con quality gate;
- recommendations con metodología;
- IA usada como ayuda, no fábrica;
- cada pieza estratégica aporta información/experiencia/utility propia;
- refreshes tienen hipótesis y datos;
- el propósito del sitio sigue siendo reconocible.
